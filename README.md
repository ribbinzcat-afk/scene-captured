# Scene Captured

Extension สำหรับ SillyTavern — เลือกข้อความในซีน แล้วให้ AI เขียน image prompt ให้ ก่อนส่งต่อไปเจนภาพ (เน้น NovelAI แต่รองรับ backend อื่นด้วย)

## ฟีเจอร์

- **เลือกข้อความบางส่วน** (ลากเลือกใน `.mes_text`) หรือกดปุ่มกล้อง 📷 ที่แถบปุ่มของข้อความ เพื่อจับ "ทั้งข้อความ" — ส่งไปให้ AI (เลือก Connection Profile ได้) เขียน prompt ให้
- **ดึงข้อมูล Character Card / Persona / World Info มาช่วยเขียน prompt ด้วย** (เปิดเป็นค่าเริ่มต้น ปิดได้ในหน้าตั้งค่า) — ทำให้ลักษณะตัวละคร (สีผม สีตา ฯลฯ) สม่ำเสมอทุกครั้ง แม้ข้อความที่เลือกจะไม่ได้พูดถึงเลยก็ตาม เพราะปกติแล้วจะพูดถึงแค่ตอนบทแรก ๆ ไม่พูดซ้ำทุกข้อความ
- **แยก prompt ตามตัวละคร** ได้ในหน้าต่างแก้ไข — เพิ่ม/ลบ/เลื่อนลำดับตัวละคร ตั้งตำแหน่งด้วยตาราง 5×5
- **4 backend สำหรับ image gen**:
  - `NovelAI (ผ่าน SillyTavern)` — ใช้ token ที่เซฟไว้ใน ST อยู่แล้ว ง่ายที่สุด แต่ **ไม่แยกตัวละคร** (ST ตัดฟีเจอร์นี้ทิ้งที่ฝั่ง server)
  - `NovelAI (ตรง — แยกตัวละครได้)` — ยิงตรงไป NovelAI ผ่าน CORS proxy ของ ST รองรับแยก prompt ตัวละครจริง
  - `ใช้ Image Generation ของ SillyTavern` — ยืม `/imagine` ของ ST เอง ใช้ได้กับทุก source ที่ ST รองรับ (Comfy, A1111, DALL-E, ...)
  - `Custom API` — ยิง URL ที่ตั้งเอง พร้อม body template ที่แทนค่าได้
- **ช่อง prefix / negative prompt / ขนาดภาพ / พารามิเตอร์ NovelAI** (model, sampler, scheduler, steps, scale, seed, SMEA, SMEA DYN, Decrisper, Variety+)
- **เจนอัตโนมัติทุก ๆ n ข้อความ** — ให้ AI เลือกซีนเองจากข้อความล่าสุด (โหมดแจ้งเตือน หรือเจนภาพให้อัตโนมัติเลย)
- **แทรกรูปเข้าข้อความ** ได้ทั้งบน/ล่าง, กด **เจนใหม่** (prompt เดิม สุ่ม seed ใหม่), **แก้ prompt**, **ก๊อป prompt**, **ลบรูป** ได้จากแถบปุ่มของข้อความ

หน้าตั้งค่าออกแบบให้ **ใช้งานง่ายตั้งแต่เปิดมา** — ค่าที่ต้องรู้จริง ๆ (เลือก backend, prefix, negative, สัดส่วนภาพ, เปิด/ปิดอัตโนมัติ) อยู่ให้เห็นเลย ส่วนค่าทางเทคนิค (sampler, seed, headers, body template ฯลฯ) พับเก็บไว้ใต้ลิงก์ **"ตั้งค่าขั้นสูง"** ในแต่ละหมวด — ไม่ต้องรู้ก็ใช้งานได้ปกติ ค่อยกดดูตอนอยากปรับละเอียดขึ้น

## รูปที่เจนจะถูกส่งให้ AI เห็นด้วยไหม (context) / เปลืองพื้นที่ไหม

ขึ้นอยู่กับ **"วิธีแทรกรูป"** ในหน้าตั้งค่า (หมวด "การแทรกรูป"):

- **แบบมีปุ่ม swipe ดูรูปเก่าได้ (ค่าเริ่มต้น)** — ใช้ระบบ media ของ SillyTavern เอง (เหมือนฟีเจอร์ Generate Image ในตัว) ได้ปุ่มเลื่อนดูรูปเก่า/regen มาฟรี **แต่ถ้าตั้งค่า SillyTavern ไว้แบบนี้พร้อมกัน**: (1) ใช้ Chat Completion API (OpenAI/Claude/Gemini ฯลฯ) **และ** (2) โมเดลที่เลือกดูรูปได้ (vision) **และ** (3) ติ๊ก "Send inline media" ไว้ (ค่าเริ่มต้นของ ST คือติ๊กอยู่) — รูปที่เจนจะถูกส่งเข้า context จริงทุกครั้งที่ AI ตอบข้อความถัดไป กินโควตา token เพิ่ม (ยืนยันจากซอร์สโค้ด ST 2026-08-19 — ST ไม่แยกว่ารูปมาจาก extension ไหน ปฏิบัติเหมือนรูปที่อัปโหลดเองทุกอย่าง) ถ้าไม่อยากให้เกิดเรื่องนี้กับรูปทุกประเภท (ไม่ใช่แค่ของ extension นี้) ปิดได้ที่ checkbox "Send inline media" ในหน้าตั้งค่า Chat Completion ของ ST
- **แบบไม่ส่งเข้า context เลย** — extension จะฝังรูปเป็น `&lt;img&gt;` ไว้ใน `extra.display_text` (ช่องสำหรับแสดงผลอย่างเดียว) แทนที่จะใช้ `extra.media` — ข้อความจริงที่ส่งให้ AI (`.mes`) ไม่ถูกแตะเลย และ ST ก็ไม่อ่าน `extra.media` เพื่อส่งรูปเข้า context ในโหมดนี้ **การันตีว่ารูปไม่มีทางถูกส่งให้ AI เห็น** ไม่ว่าจะตั้งค่า Chat Completion แบบไหน — ข้อแลกคือไม่มีปุ่ม swipe ดูรูปเก่า (โชว์ได้ทีละรูป) และ **รูปเก่าจะถูกลบทิ้งจากดิสก์จริง ๆ ทุกครั้งที่มีรูปใหม่มาแทน** (ไม่สะสม)

เรื่องพื้นที่เก็บข้อมูล: ไม่ว่าโหมดไหน รูปที่เจนจะถูกบันทึกเป็นไฟล์จริงใน `data/&lt;user&gt;/user/images/` เสมอ — **ปุ่ม "ลบรูป" ตอนนี้ลบไฟล์จริงออกจากดิสก์ด้วย** (ไม่ใช่แค่เอาออกจากที่แสดงผล) แต่ถ้าใช้โหมด gallery แล้ว regen หลายรอบ ไฟล์รูปเก่าที่ยังกด swipe ย้อนดูได้จะยังอยู่บนดิสก์ (ตั้งใจเก็บไว้ให้ swipe กลับไปดูได้ — ถ้าไม่อยากสะสมไฟล์ ให้ใช้โหมด "ไม่ส่งเข้า context" แทน จะลบไฟล์เก่าให้อัตโนมัติทุกครั้ง)

## การติดตั้ง

1. คัดลอกโฟลเดอร์ `scene-captured/` ไปไว้ที่ `SillyTavern/public/scripts/extensions/third-party/scene-captured`
2. รีเฟรช SillyTavern
3. เปิดลิ้นชัก Extensions (ไอคอนก้อนเมฆ) → หา "Scene Captured"

## วิธีใช้เบื้องต้น

1. เปิดหน้าตั้งค่า Scene Captured → เลือก Connection Profile ที่จะใช้เขียน prompt (ไม่เลือก = ใช้ API หลักของ ST)
2. ลากเลือกข้อความในแชท → ปุ่ม "📸 จับซีนนี้" จะโผล่ใกล้จุดที่เลือก กดเพื่อเริ่ม
   - หรือกดปุ่มกล้อง 📷 ที่แถบปุ่มของข้อความ เพื่อจับ "ทั้งข้อความ" นั้น
3. รอ AI เขียน prompt เสร็จ จะเปิดหน้าต่างแก้ไขให้ — แก้ base/negative/ตัวละครได้ตามต้องการ
4. กด **"สร้างภาพ"** เพื่อบันทึกแล้วเจนภาพทันที หรือ **"บันทึก prompt อย่างเดียว"** เพื่อเก็บไว้เจนทีหลัง

## ตั้งค่า NovelAI (ตรง — แยกตัวละคร)

โหมดนี้เป็นโหมดเดียวที่ส่ง prompt แยกตัวละครจริงไปให้ NovelAI (ผ่าน `characterPrompts` และ `v4_prompt.caption.char_captions`) เพราะ SillyTavern เองตัดฟีเจอร์นี้ทิ้งที่ endpoint `/api/novelai/generate-image` (ส่งเป็น `[]` ตายตัวเสมอ ไม่ว่าจะส่งอะไรไปเพิ่มก็ถูกทิ้ง)

**ต้องทำ 2 อย่างก่อนใช้:**

1. เปิด CORS proxy ของ SillyTavern — แก้ `config.yaml` ที่ root ของ SillyTavern:
   ```yaml
   enableCorsProxy: true
   ```
   แล้วรีสตาร์ทเซิร์ฟเวอร์ (หรือใช้ flag `--corsProxy` ตอนรัน)
2. กรอก NovelAI Token ในหน้าตั้งค่า Scene Captured (⚠️ เก็บเป็น plaintext ใน `settings.json` — อย่าแชร์ไฟล์นี้ให้ใคร)

กดปุ่ม "ทดสอบการเชื่อมต่อ" เพื่อเช็คว่า token + CORS proxy ใช้ได้จริง

> ⚠️ **endpoint ตรวจสอบ (ปุ่ม "ทดสอบการเชื่อมต่อ") อาจขึ้น error ทั้งที่ token ใช้งานได้จริง** — พบว่า `/user/subscription` ของ NovelAI บางครั้งตอบ `{"statusCode":400,"message":"Please refresh NovelAI.net..."}` แม้ token ใช้เจนภาพได้ปกติ (ยืนยันแล้ว 2026-08-19) ถ้าเจอ error นี้ ให้ลองกด "จับซีนนี้" แล้วสร้างภาพจริงดูอีกทาง อย่าเชื่อผลจากปุ่มทดสอบอย่างเดียว

✅ **ยืนยันแล้วว่า `characterPrompts` / `v4_prompt.caption.char_captions` / `use_coords` ทำงานได้จริง** (ทดสอบกับ NovelAI จริง 2026-08-19) — ส่งตัวละคร 2 คนพร้อมตำแหน่ง `center: {x, y}` ที่ต่างกัน ได้ภาพที่แยกตัวละครถูกต้องตามตำแหน่งจริง ไม่มีลักษณะปนกัน

**ข้อควรระวังตอนใช้หลายตัวละคร**: **ห้ามมีคำว่า `solo` หรือระบุแค่ `1girl`/`1boy` เดี่ยว ๆ ใน base prompt** ถ้าใน `characters` มีมากกว่า 1 คน — จะขัดกับการแยกตัวละครของ NovelAI ทำให้เจนออกมาเหลือแค่คนเดียว (พิสูจน์แล้วจากการทดสอบจริง) ให้ระบุจำนวน/เพศรวมให้ตรง เช่น `"2characters, 1girl, 1boy"` แทน — ตอนนี้ prompt คำสั่งระบบ (system prompt) เริ่มต้นของ extension สั่งให้ AI หลีกเลี่ยงเรื่องนี้ไว้แล้ว แต่ถ้าแก้ prompt เองหรือ base prompt เดิมมาจากการจับซีนที่เคยเป็นคนเดียว แล้วเพิ่มตัวละครทีหลัง ให้เช็ค/แก้ base prompt ด้วยตัวเองก่อนกดสร้างภาพ

## ตั้งค่า Custom API

ใช้โหมดนี้เมื่อมี API ของ provider อื่น (ที่ไม่ใช่ NovelAI ตรง ๆ) ที่มีโมเดลตระกูล NAI หรือโมเดลอื่นอยู่ในนั้น

### API Key

กรอกคีย์ในช่อง **"API Key"** — extension จะแทรกเป็น header ให้อัตโนมัติ **ไม่ต้องเขียนเองในช่อง Headers** โดย:

- **ชื่อ Header** ค่าเริ่มต้นคือ `Authorization` — เปลี่ยนได้ถ้า provider ใช้ชื่ออื่น (เช่น `x-api-key`)
- **Prefix ก่อนคีย์** ค่าเริ่มต้นคือ `Bearer ` (มีเว้นวรรคท้าย) — บาง provider ไม่ต้องมี prefix เลย ก็ลบให้ว่างได้

ผลลัพธ์ที่ส่งไปคือ header `<ชื่อ Header>: <Prefix><API Key>` เช่น `Authorization: Bearer sk-xxxxx`

⚠️ เก็บเป็น plaintext ใน `settings.json` เหมือนกับ NovelAI Token — อย่าแชร์ไฟล์นี้ให้ใคร

### โหลดรายชื่อโมเดลจาก provider

ถ้า provider มี endpoint สำหรับ list โมเดล (GET) กรอก URL ในช่อง **"URL สำหรับโหลดรายชื่อโมเดล"** แล้วกด **"โหลดรายชื่อโมเดล"** — extension จะยิงไปพร้อม header เดียวกับตอนเจนภาพ (รวม API Key ที่ตั้งไว้) แล้วเติมชื่อโมเดลลง dropdown ให้เลือก

- ถ้า response เป็น `{"data": [{"id": "nai-diffusion-4-5-full", ...}, ...]}` → ใส่ **"Path ของ array รายชื่อโมเดล"** เป็น `data`
- ถ้า response เป็น array ตรง ๆ (เช่น `["model-a", "model-b"]` หรือ `[{"id": "..."}]`) → เว้น path ว่างไว้
- เลือกจาก dropdown แล้วชื่อโมเดลจะถูกเติมลงช่อง **"Model ที่จะใช้"** ให้เอง (พิมพ์เองตรง ๆ ก็ได้ถ้าไม่มี endpoint list โมเดล)

ค่าที่เลือกใช้ผ่าน placeholder `{{model}}` ใน Body Template

### Body Template

ตั้ง URL, Method, Headers อื่น ๆ เพิ่มเติม (JSON), และ Body Template ที่ใช้ placeholder แทนค่าได้:

- `{{model}}` — โมเดลที่เลือก/พิมพ์ไว้ด้านบน
- `{{prompt}}` — prompt ที่รวม prefix + base + ตัวละครที่เปิดใช้แล้ว (ยุบเป็น prompt เดียว)
- `{{negative}}` — negative prompt
- `{{width}}` / `{{height}}` — ขนาดภาพ (ตัวเลขดิบ ไม่ต้องมี quote ครอบใน template)
- `{{seed}}` — seed (ตัวเลขดิบ)
- `{{characters_json}}` — array ของตัวละครที่เปิดใช้ `[{name, prompt, uc, x, y}]` (เป็น JSON array ดิบ ไม่ต้องมี quote ครอบ)

ตัวอย่าง template เริ่มต้น:
```json
{
  "model": "{{model}}",
  "prompt": "{{prompt}}",
  "negative_prompt": "{{negative}}",
  "width": {{width}},
  "height": {{height}},
  "seed": {{seed}},
  "characters": {{characters_json}}
}
```

ตั้ง **"path ของรูปใน response"** ให้ตรงกับ API ที่ใช้ (เช่น `images.0` ถ้า response เป็น `{"images": ["base64..."]}` หรือเว้นว่างถ้า response ทั้งก้อนเป็นรูปเลย) — รองรับทั้ง base64 ดิบ, `data:image/...;base64,...`, และ URL ที่ขึ้นต้นด้วย `http`

## ข้อจำกัดที่รู้อยู่แล้ว

- **`NovelAI (ผ่าน SillyTavern)` ไม่แยกตัวละคร** — ยุบรวม prompt ทุกตัวละครเข้า base prompt เดียว (ข้อจำกัดของ endpoint ฝั่ง ST เอง)
- **`ใช้ Image Generation ของ SillyTavern`** ไม่ส่ง model/sampler/steps/scale ของ NovelAI ไปด้วย เพราะ source อื่นที่ไม่ใช่ NAI จะไม่รู้จักชื่อพวกนี้ — ใช้ค่าที่ตั้งไว้ใน "Image Generation" ของ ST เองแทน
- โหมด NovelAI (ตรง) ยังไม่ได้ทดสอบกับ subscription จริง (ดูหมายเหตุด้านบน)
- ก๊อป prompt ใช้ `navigator.clipboard` — ต้องเป็น secure context (https หรือ localhost) และเบราว์เซอร์อนุญาต clipboard access
